# 04. 문제 출제 기준

Claude Code가 문제(고정 문제·템플릿)를 만들 때, 그리고 사용자가 문제를 직접 추가할 때 따르는 기준이다.

## 1. 기본 원칙

1. **자체 창작**: Claude가 만드는 문제는 새로 쓴다. 시중 교재·문제집·복원 기출의 문장이나 예시 데이터를 옮기지 않는다. 같은 개념을 묻되 상황·데이터·표현을 새로 만든다.
2. **시험과 같은 결**: 4지선다, "옳은 것은 / 옳지 않은 것은 / 결과로 알맞은 것은" 형태, Oracle 문법 기준.
3. **정답은 검증 가능해야 한다**: SQL 결과를 묻는 문제는 sql.js로 실행해 정답을 확인한다. 실행할 수 없는 Oracle 전용 문법은 해설에 근거(동작 규칙)를 명시한다.
4. **해설이 본체다**: 문제보다 해설에 더 공을 들인다 (§4).

## 3. 문제 유형

| type | 이름 | 설명 | 예 |
|---|---|---|---|
| `concept` | 개념형 | 정의·특징의 옳고 그름 | "식별자의 특징으로 옳지 않은 것은?" |
| `sql_result` | 결과예측형 | 테이블+SQL → 결과(건수, 값, 결과표) | "다음 SQL의 결과 건수는?" |
| `sql_error` | 오류찾기형 | 실행 오류가 나거나 의도와 다른 SQL 찾기 | "다음 중 오류가 발생하는 SQL은?" |
| `sql_equivalent` | 동치형 | 같은 결과를 내는 SQL 찾기 | "다음 SQL과 결과가 같은 것은?" |
| `sql_fill` | 빈칸형 | SQL의 빈칸에 들어갈 것 | "(ㄱ)에 들어갈 키워드는?" |
| `modeling` | 모델링 해석형 | ERD·관계 설명을 보고 판단 | "다음 ERD에서 관계 차수로 옳은 것은?" |
| `scenario` | 시나리오형 | DML/TCL을 순서대로 실행한 최종 상태 | "다음을 차례로 수행한 뒤 SELECT 결과는?" |

단원마다 최소 3가지 유형이 섞이도록 만든다. 난이도는 1(기본 개념) / 2(응용, 함정 1개) / 3(함정 2개 이상, 여러 개념 결합)으로, 단원별 대략 3:5:2.

## 4. 해설 작성 규칙

사용자는 **항목별로 끊기는 설명보다, 흐름이 이어지는 깊이 있는 설명**을 선호한다.

1. 첫 문단: 정답과 핵심 이유를 한두 문장으로.
2. 둘째 문단: 개념이 왜 그렇게 동작하는지 흐름 있게 설명. SQL이면 실행 순서(FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY)를 따라가며 중간 결과가 어떻게 변하는지 보여 준다.
3. 셋째 문단: 오답 보기들이 왜 틀렸는지, 어떤 착각을 노린 보기인지.
4. SQL 문제는 예시 테이블과 **실행 결과 표**를 해설에 포함한다. 예시 데이터는 결과 차이가 눈에 보이게 구성한다 (예: GROUP BY라면 같은 그룹이 여러 행 있어 원본과 집계 결과가 확연히 다르도록, NULL 문제라면 NULL 행을 2개 이상).
5. 마지막에 "시험 포인트" 한 줄: 이 문제에서 기억할 함정.
6. **①②③④ 기호는 보기 번호를 가리킬 때만 쓴다.** 앱이 보기를 섞으면 해설·시험 포인트 속 ①~④를 화면에 보이는 번호로 자동으로 바꿔 보여 주기 때문이다 (T3-5). 행 번호나 단계는 "1번 행", "(1)" 등 다른 표기를 쓴다.

## 5. 문제 JSON 형식

파일 위치: `src/data/questions/{단원코드}.json` (예: `S1-05.json`), 내용은 Question 배열.

```json
{
  "id": "S1-05-0003",
  "subject": 2,
  "chapter": "S1-05",
  "topic": "COUNT(*)와 COUNT(컬럼)의 차이",
  "type": "sql_result",
  "difficulty": 2,
  "stem": "다음 [EMP] 테이블에 SQL을 실행했을 때 결과로 알맞은 것은?",
  "tables": [
    {
      "name": "EMP",
      "columns": ["EMPNO", "DEPT", "BONUS"],
      "rows": [
        [1, "A", 100],
        [2, "A", null],
        [3, "B", 200],
        [4, "B", null],
        [5, "B", 300]
      ]
    }
  ],
  "sql": "SELECT DEPT, COUNT(*) AS C1, COUNT(BONUS) AS C2\nFROM EMP\nGROUP BY DEPT\nORDER BY DEPT;",
  "choices": [
    "A:2,1 / B:3,2",
    "A:2,2 / B:3,3",
    "A:1,1 / B:2,2",
    "A:2,1 / B:3,3"
  ],
  "answer": 1,
  "fixedOrder": false,
  "explanation": "정답은 ①입니다. COUNT(*)는 행 자체를 세고, COUNT(BONUS)는 BONUS가 NULL이 아닌 행만 셉니다...",
  "examPoint": "집계 함수는 NULL을 무시하지만 COUNT(*)만은 예외다.",
  "tags": ["NULL", "집계함수"],
  "source": "claude",
  "verify": { "executable": true }
}
```

| 필드 | 필수 | 규칙 |
|---|---|---|
| `id` | ✔ | `{단원코드}-{4자리 번호}`. 직접 추가 문제는 `U-{단원코드}-{번호}` |
| `subject` | ✔ | 1 또는 2, 단원 코드와 일치 |
| `chapter` | ✔ | §2 코드표에 있는 값 |
| `topic` | ✔ | 20자 내외 세부 주제 |
| `type` | ✔ | §3 값 |
| `difficulty` | ✔ | 1~3 |
| `stem` | ✔ | Markdown. 보기에 해당하는 내용은 넣지 않는다 |
| `tables` | | 예시 테이블. `rows`의 NULL은 JSON `null` |
| `sql` | | Oracle 문법 원문 (화면 표시용) |
| `sqlExec` | | sql.js 실행용 SQL. Oracle 문법을 그대로 실행할 수 없을 때만 (§6) |
| `choices` | ✔ | 정확히 4개, 서로 달라야 함 |
| `answer` | ✔ | 1~4 |
| `fixedOrder` | | 보기 순서를 섞으면 안 되는 문제면 true. 보기가 크기 순(`1건`~`4건`)이거나, 보기 문장이 다른 보기를 가리키면("①과 ③ 모두") 반드시 true (테스트가 ①~④ 포함 여부를 검사) |
| `explanation` | ✔ | §4 규칙 |
| `examPoint` | ✔ | 한 줄 |
| `tags` | | 검색용 |
| `source` | ✔ | `claude` / `user` |
| `verify.executable` | | true면 테스트가 `sqlExec ?? sql`을 실행해 정답 보기와 결과를 대조 (대조 방법은 `verify.expect`로 지정: `rowCount`, `value`, `resultTable`) |
| `verify.expect` | | `rowCount`: 마지막 결과의 행 수 = 정답 보기 속 첫 숫자 (보기 예: `3건`) / `value`: 마지막 결과 첫 행의 값들을 `, `로 이은 문자열 = 정답 보기 (NULL은 `NULL`, 보기 예: `750, 1050, 1050`) / `resultTable`: 아직 미지원. 테이블은 `tables`의 `name`으로 만들어지므로 실행 검증 문제의 테이블에는 `name`이 필요 (`tests/questions-sql.test.ts`) |

## 6. Oracle ↔ SQLite 변환 규칙

화면에는 Oracle 문법을 보여 주고, sql.js 실행에는 아래처럼 바꾼 `sqlExec`를 쓴다. **결과가 같다는 것이 보장될 때만** 템플릿·실행 검증에 사용한다.

| Oracle (화면) | SQLite (실행) | 주의 |
|---|---|---|
| `NVL(a, b)` | `IFNULL(a, b)` | 같음 |
| `NVL2(a, b, c)` | `CASE WHEN a IS NOT NULL THEN b ELSE c END` | |
| `DECODE(a, x, r1, r2)` | `CASE WHEN a = x THEN r1 ELSE r2 END` | DECODE는 NULL=NULL을 같다고 봄 → `a IS x`로 변환 |
| `MINUS` | `EXCEPT` | 같음 |
| `SUBSTR`, `INSTR`, `LENGTH`, `UPPER`, `LOWER`, `TRIM` | 동일 이름 | INSTR 3·4번째 인자는 SQLite에 없음 → 사용 금지 |
| `a / b` (정수) | `a * 1.0 / b` | Oracle은 7/2=3.5, SQLite는 3 |
| `''` (빈 문자열) | `NULL` | **Oracle은 빈 문자열을 NULL로 취급** → 템플릿 데이터에서 빈 문자열 사용 금지, 이 함정은 고정 문제로 |
| `ROWNUM <= n` | 의미에 따라 `LIMIT n` 또는 `ROW_NUMBER()` | ROWNUM은 ORDER BY **전에** 매겨짐. `SELECT ... WHERE ROWNUM<=3 ORDER BY sal` 은 "아무 3행을 고른 뒤 정렬" → 실행 시 rowid 순 3행을 고른 뒤 정렬하는 SQL로 변환 |
| `FETCH FIRST n ROWS ONLY` | `LIMIT n` | `WITH TIES`는 변환 금지 |
| NULL 정렬 | `ORDER BY x NULLS LAST` 명시 | Oracle 기본: ASC에서 NULL이 마지막, SQLite는 처음 → 항상 명시해서 실행 |
| `ROLLUP/CUBE/GROUPING SETS` | 지원 안 됨 | UNION ALL 조합으로 직접 작성하거나 JS로 계산 |
| `CONNECT BY` | 재귀 CTE(`WITH RECURSIVE`) | LEVEL·정렬 순서(깊이 우선) 재현 필요 → 고정 문제 권장 |
| `PIVOT/UNPIVOT`, `REGEXP_*`, `MERGE` | 지원 안 됨 | 고정 문제로 |
| `SYSDATE`, 날짜 연산 | 고정 문자열 날짜 | 템플릿에서 날짜 연산 사용 지양 |

## 7. 템플릿 목록 (Phase 4)

각 템플릿은 데이터를 무작위로 만들고, **정답 쿼리**와 **함정 쿼리**(흔한 실수를 구현한 쿼리)를 함께 실행해 보기를 만든다.

| ID | 단원 | 문제 형태 | 정답 | 함정 보기 생성 방법 |
|---|---|---|---|---|
| TP01 | S1-04 | WHERE 조건(AND/OR 우선순위, BETWEEN, IN, LIKE) 결과 건수 | 결과 건수 | 괄호를 다르게 묶은 쿼리, BETWEEN 경계 제외, LIKE `_`를 `%`로 착각 |
| TP02 | S1-03/M2-04 | NULL과 집계(SUM/AVG/COUNT) 결과값 | 값 | AVG에 NULL을 0으로 포함, COUNT(*)와 혼동, NULL+숫자를 숫자로 계산 |
| TP03 | S1-05 | GROUP BY + HAVING 결과 행 수 또는 결과표 | 결과 | HAVING을 WHERE처럼 적용(집계 전 필터), COUNT(컬럼)↔COUNT(*) |
| TP04 | S1-08 | INNER vs LEFT/RIGHT/FULL OUTER JOIN 결과 건수 | 건수 | 조인 종류를 바꾼 쿼리, ON 조건을 WHERE로 옮긴 쿼리 |
| TP05 | S2-02 | UNION / UNION ALL / INTERSECT / MINUS 결과 건수 | 건수 | 다른 집합 연산자로 바꾼 결과, 중복 제거 여부 착각 |
| TP06 | S2-01 | IN / NOT IN / EXISTS 서브쿼리 결과 (NOT IN + NULL 함정 포함) | 건수 | NOT IN 서브쿼리에 NULL이 있을 때 0건이 되는 점을 모른 경우 |
| TP07 | S2-04 | RANK / DENSE_RANK / ROW_NUMBER 특정 행의 값 | 값 | 다른 순위 함수의 값, PARTITION BY 누락 |
| TP08 | S2-04 | 집계 윈도우 함수(SUM OVER, ORDER BY 누적) 특정 행의 값 | 값 | 누적 대신 전체 합, ROWS vs RANGE(동순위 처리) |

| TP10 | S3-01/S3-02 | INSERT/UPDATE/DELETE + SAVEPOINT/ROLLBACK/COMMIT 시나리오 후 최종 건수·값 | 값 | ROLLBACK TO 지점 착각, ROLLBACK이 COMMIT 이전까지 되돌린다는 점 착각 |
| TP11 | S1-03 | 문자 함수(SUBSTR, INSTR, REPLACE, LENGTH) 결과 값 | 값 | 위치를 0부터 셈, 길이 인수를 끝 위치로 착각, REPLACE가 첫 번째만 바꾼다고 착각 |
| TP12 | S1-03 | CASE 등급(WHEN 순서, ELSE 없음) 결과 건수 | 건수 | 앞 WHEN에 걸린 행까지 셈, 경계값 제외, ELSE 없을 때 NULL을 모름 |
| TP13 | S1-06 | ORDER BY와 NULL 위치(ASC/DESC, NULLS FIRST/LAST) 첫 행 | 값 | NULL을 가장 작은 값으로 봄, 정렬 방향 반대, NULL 행 제외 |
| TP14 | S1-07 | NON-EQUI 조인(BETWEEN LOSAL AND HISAL) 결과 건수 | 건수 | 경계값 제외, 범위 밖 사원 포함, 조인 조건 누락(곱집합) |
| TP15 | S2-03 | ROLLUP / CUBE / GROUPING SETS 결과 행 수 | 건수 | 다른 그룹 함수로 바꾼 행 수, 소계·총계 행 누락 (실행은 UNION ALL, JS로 대조) |
| TP16 | S2-06 | 계층형 질의(START WITH, PRIOR 방향, LEVEL) 결과 건수 | 건수 | PRIOR 방향 반대, 시작 행 제외, 루트 LEVEL을 0으로 봄 (실행은 재귀 CTE, JS로 대조) |
| TP17 | S2-01 | 연관 서브쿼리(부서 평균 비교, EXISTS) 결과 건수 | 건수 | 전체 평균과 비교, NOT EXISTS와 혼동, 부서 대신 사원 수를 셈 |
| TP18 | S3-01 | INSERT → UPDATE → DELETE 연속 실행 후 건수·합계 | 값 | DELETE 누락, DELETE가 UPDATE 전 값으로 판단, 방금 넣은 행에 UPDATE 미적용 |

템플릿 공통 규칙:
- 테이블 행 수 5~12, 컬럼 3~5. 값은 작고 읽기 쉬운 숫자(10 단위 등).
- 결과 차이가 생기도록 데이터를 강제한다: NULL 문제면 NULL ≥ 2행, 조인 문제면 짝 없는 행이 양쪽에 ≥ 1행, 그룹 문제면 그룹당 ≥ 2행.
- 정답과 함정 보기 값이 우연히 같아지면 데이터를 다시 생성(최대 20회).
- 해설은 문장 틀 + 실제 실행 결과 표(중간 단계 포함)로 자동 생성한다.

## 8. Claude Code에게 문제 생성을 시킬 때의 요청 형식

```
docs/04_문제출제기준.md를 따라 {단원코드} 단원 고정 문제 {N}개를 만들어 줘.
- 유형 분포: concept {a}, sql_result {b}, sql_error {c}, ... (단원 성격에 맞게 조정 가능)
- 난이도 분포: 1:2:3 = 3:5:2
- 기존 src/data/questions/{단원코드}.json에 있는 문제와 주제·데이터가 겹치지 않게
- 실행 가능한 SQL 문제는 verify.executable=true로 하고 테스트로 정답 검증
- 끝나면 새로 만든 문제 중 3개를 골라 본문·보기·정답만 보여 줘 (검수용)
```

한 번에 15~20개 이하로 나눠 요청하면 품질과 사용량 관리에 유리하다.
