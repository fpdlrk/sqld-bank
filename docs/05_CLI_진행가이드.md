# 05. VS Code + Claude Code(CLI) 진행 가이드

## 1. 처음 한 번: 프로젝트 준비

1. 원하는 위치에 `sqld-bank` 폴더를 만든다.
2. 이 문서 묶음을 아래처럼 넣는다.
   ```
   sqld-bank/
   ├─ CLAUDE.md
   ├─ README.md
   └─ docs/
      ├─ 01_프로젝트계획서.md
      ├─ 02_작업지시서.md
      ├─ 03_상세단위업무계획서.md
      ├─ 04_문제출제기준.md
      └─ 05_CLI_진행가이드.md
   ```
3. VS Code에서 `파일 > 폴더 열기`로 `sqld-bank`를 연다.
4. 터미널(`Ctrl + `` ` ``)에서 `node -v`, `git --version`으로 설치를 확인한다. Node는 20 이상이면 된다.
5. 같은 터미널에서 `claude`를 실행한다. **반드시 프로젝트 폴더 안에서 실행**해야 `CLAUDE.md`를 자동으로 읽는다.

## 2. 문서가 Claude Code와 어떻게 연결되나

`CLAUDE.md`는 Claude Code가 세션을 시작할 때마다 자동으로 읽는 파일이다. 여기에 기술 스택, 폴더 구조, 작업 원칙, "하지 말 것"이 적혀 있어서, 매번 "React로 해 줘, 서버 만들지 마" 같은 말을 반복할 필요가 없다. 반면 `docs/` 안의 문서는 자동으로 읽히지 않는다. 그래서 작업지시서의 지시문은 "docs/03의 T3-2를 진행해 줘"처럼 문서를 가리키도록 써 두었고, Claude Code는 그 말을 보고 해당 문서를 열어 읽는다. 특정 파일을 확실히 보게 하고 싶으면 프롬프트에 `@docs/04_문제출제기준.md`처럼 `@`로 파일을 지정하면 된다.

즉 역할 분담은 이렇다. **CLAUDE.md = 항상 지킬 규칙**, **01·04 = 판단 기준(설계·출제)**, **03 = 할 일 목록과 완료 기준**, **02 = 실제로 붙여 넣는 말**.

## 3. 한 번의 작업 사이클

```
① 지시문 붙여넣기 (02에서 복사)
      ↓
② 계획 확인 — 큰 작업은 Claude가 계획을 먼저 보여 줌 → 괜찮으면 "진행해", 아니면 수정 요청
      ↓
③ 실행 — 파일 수정·명령 실행 시 권한을 물어보면 내용을 보고 허용
      ↓
④ 완료 보고 확인 — "확인 방법"대로 직접 눌러 본다 (npm run dev → 브라우저)
      ↓
⑤ 문제 있으면 그 자리에서 수정 요청 / 괜찮으면 내가 직접 커밋 → 다음 지시
```

④에서 직접 확인하는 습관이 가장 중요하다. Claude Code가 "완료"라고 해도 화면을 한 번 눌러 보면 의도와 다른 부분이 꼭 보인다. 그때 바로 말하는 게 나중에 고치는 것보다 훨씬 싸다.

## 4. 알아 두면 좋은 조작

| 조작 | 용도 |
|---|---|
| `Shift + Tab` | 모드 전환. **계획 모드(plan mode)**로 두면 코드를 고치지 않고 계획만 세움 → 큰 Task 시작 전에 유용 |
| `Esc` | 진행 중인 작업 중단 (방향이 이상할 때 바로 멈추기) |
| `/clear` | 대화 내용을 비우고 새로 시작. **Task가 바뀔 때마다** 쓰면 이전 맥락이 섞이지 않고 사용량도 아낌 |
| `/compact` | 대화가 길어졌을 때 요약해서 이어 가기 |
| `@파일경로` | 특정 파일을 읽게 지정 |
| `claude -c` | 터미널을 껐다 켠 뒤 직전 대화 이어 가기 |
| `claude --resume` | 예전 대화 목록에서 골라 이어 가기 |

## 5. 개발 서버 띄워서 확인하기

Claude Code 터미널과 **별도로** VS Code에서 터미널을 하나 더 열고(`+` 버튼) 다음을 실행해 둔다.

```
npm run dev
```

출력되는 주소(보통 `http://localhost:5173`)를 브라우저로 열어 두면, Claude Code가 파일을 고칠 때마다 화면이 자동으로 새로고침된다. 모바일 화면은 브라우저 개발자도구(F12) → 기기 모드 토글로 375px 폭을 확인한다. 같은 와이파이의 실제 폰으로 보고 싶으면 `npm run dev -- --host`로 실행하고, 출력된 `Network:` 주소를 폰에서 연다.

## 6. 진행 리듬 추천

- **하루 1~2 Phase**를 목표로, Task가 바뀔 때 `/clear`.
- 세션 시작 첫 마디는 `docs/03 기준으로 다음 할 Task가 뭔지 알려 줘` → 확인 후 해당 지시문 붙여넣기.
- Phase가 끝날 때마다 실제로 한 번 써 본다. 특히 Phase 3이 끝나면 샘플 문제로 공부 흐름을 체험해 보고, 불편한 점을 Phase 4 들어가기 전에 고친다.
- **Phase 8(문제 생성)은 사용량이 가장 많이 드는 구간**이다. 한 번에 15~20문제씩, 하루 몇 단원씩 나눠 진행하고, 만들어진 문제를 풀어 보는 것 자체를 공부 시간으로 쓰면 된다.
- MVP(Phase 0~5 + 단원당 10문제 + Phase 9)를 먼저 끝내고 폰에서 공부를 시작하면, 나머지 기능은 쓰면서 필요한 순서대로 붙여도 된다.

## 7. 커밋 = 저장 지점

커밋과 푸시는 **사용자가 직접** 한다. `CLAUDE.md`에 Claude Code는 커밋·푸시를 하지 않고, Task가 끝날 때마다 "바뀐 파일 + 커밋 메시지"만 제안하도록 적어 두었다.

커밋은 게임의 세이브 포인트와 같다. Task 하나가 끝나고 화면까지 확인했으면 바로 커밋해 두는 습관을 들이면, 다음 작업이 꼬였을 때 그 지점으로 돌아갈 수 있다.

### 7.1 처음 한 번 (T0-3 끝난 뒤)
VS Code 터미널(Claude Code가 아닌 일반 터미널)에서:
```
git init
git add .
git commit -m "T0-3: 프로젝트 초기화"
```
GitHub 저장소를 만든 뒤(T9-2) 연결:
```
git remote add origin https://github.com/{아이디}/sqld-bank.git
git branch -M main
git push -u origin main
```

### 7.2 매 Task 끝날 때
방법은 두 가지 중 편한 쪽으로.

- **VS Code 화면으로**: 왼쪽 "소스 제어" 아이콘(가지 모양) → 바뀐 파일 목록에서 내용 확인 → 위쪽 입력칸에 Claude가 제안한 커밋 메시지 붙여넣기 → `커밋` 버튼 → 배포할 때 `변경 내용 동기화`(푸시).
- **터미널로**:
  ```
  git status                 # 무엇이 바뀌었는지
  git diff                   # 자세한 변경 내용
  git add .
  git commit -m "T3-2: 문제 채점·해설 표시 추가"
  git push                   # GitHub에 올리기 → (Phase 9 이후) 자동 배포
  ```

커밋은 자주(Task마다), 푸시는 사이트에 반영하고 싶을 때만 해도 된다. 푸시를 해야 GitHub의 사이트가 바뀐다.

### 7.3 되돌리고 싶을 때
Claude Code는 되돌리기도 직접 하지 않는다. 이렇게 물어보면 실행할 명령과 결과를 설명해 준다.
```
방금 작업이 마음에 안 들어. 마지막 커밋 상태로 되돌리려면 어떤 명령을 쓰면 되는지,
그러면 어떤 변경이 사라지는지 설명해 줘. 실행은 내가 할게.
```

### 7.4 (선택) 실수 방지 잠금
`CLAUDE.md` 규칙만으로도 대부분 지켜지지만, 아예 막아 두고 싶으면 Claude Code의 권한 설정에서 `git commit`, `git push` 명령을 거부 목록에 넣을 수 있다. Claude Code에 이렇게 요청하면 된다.
```
이 프로젝트에서 git add, commit, push, reset 명령은 실행하지 못하게 권한 설정(.claude/settings.json의 deny)을 추가해 줘.
설정 내용을 먼저 보여 주고, 어떻게 확인하는지도 알려 줘.
```

## 8. 문서를 바꾸고 싶을 때

진행하다 보면 계획이 바뀐다. 그럴 땐 코드만 고치지 말고 문서도 함께 고치게 한다.

```
모의고사에 "1과목만 10문항 미니 모의고사" 모드를 추가하고 싶어.
docs/01 범위와 화면 구성, docs/03에 Task를 추가하고, docs/02에 지시문도 추가한 다음 진행해 줘.
```

문서와 코드가 같이 움직여야 다음 세션의 Claude Code도 바뀐 계획을 알고 작업한다.
