# 01. 프로젝트 계획서 — SQLD 나만의 문제은행 (sqld-bank)

## 1. 목적

SQLD 시험을 준비하면서 자료를 찾아다니는 시간을 줄이고, **문제를 풀고 → 틀린 것을 다시 보고 → 약한 단원을 집중 공략**하는 흐름을 한곳에서 해결하는 개인용 웹사이트를 만든다.

성공 기준은 세 가지다.
- 단원별 연습과 실전형 모의고사(50문항·90분)를 PC와 모바일에서 모두 풀 수 있다.
- SQL 결과예측 문제는 열 때마다 데이터가 바뀌어 **외워서 풀 수 없다**.
- 사이트를 쓰는 동안 AI 사용량이 전혀 들지 않는다 (AI는 문제를 미리 만들 때만 사용).

## 2. 범위

| 구분 | 내용 |

- 사이트 안에서 AI에게 질문하는 기능
- 서버·백엔드 (기기 간 동기화는 Phase 10 선택 과제)

### 4.2 데이터가 어디에 사는가 — 초보자용 설명

이 사이트에는 성격이 다른 데이터가 세 종류 있고, 각각 사는 곳이 다르다.

**① 고정 문제**는 거의 바뀌지 않는 "교재" 같은 데이터다. 그래서 DB가 아니라 프로젝트 안의 JSON 파일(`src/data/questions/*.json`)로 두고, 사이트를 빌드할 때 함께 묶어서 배포한다. 문제를 추가하고 싶으면 Claude Code에게 JSON 파일에 문제를 추가해 달라고 하고 다시 배포하면 된다. 이렇게 하면 DB 없이도 문제은행이 성립한다.

**② 풀이 기록**(언제 어떤 문제를 풀었고 맞았는지, 오답노트 메모)은 사용자가 풀 때마다 계속 늘어나는 데이터다. 이건 브라우저에 내장된 작은 데이터베이스인 **IndexedDB**에 저장한다. localStorage보다 용량이 크고(수백 MB 수준), 표처럼 여러 건을 다루기 좋다. 직접 다루기 번거로워서 Dexie라는 라이브러리로 감싸 쓴다.

**③ 직접 추가한 문제**도 IndexedDB에 저장하고, 화면에서는 ①과 합쳐서 하나의 문제은행처럼 보여 준다. 마음에 드는 문제는 JSON으로 내보내서 ①로 옮길(커밋할) 수 있다.

IndexedDB의 약점은 **기기마다 따로**라는 점이다. PC에서 푼 기록은 폰에 없다. 그래서 두 가지 장치를 둔다.
- **JSON 백업/복원**: 설정 화면에서 전체 기록을 파일로 내려받고, 다른 기기에서 불러온다. (1차 해결)
- **저장소 어댑터 구조**: 모든 저장은 `StorageAdapter` 인터페이스를 거치게 만들어, 나중에 Supabase(무료 클라우드 DB) 구현체만 추가하면 기기 간 자동 동기화로 바꿀 수 있게 한다. (Phase 10)

### 4.3 템플릿 문제 엔진 — 문제가 매번 바뀌는 원리

"이 쿼리를 실행하면 몇 건이 나오는가?" 같은 문제를 문장으로 고정하지 않고 **규칙(템플릿)**으로 만든다.

1. 시드(seed) 숫자로 난수 생성기를 초기화한다. 같은 시드 → 항상 같은 문제가 나온다.
2. 템플릿이 규칙대로 예시 테이블 데이터를 만든다 (예: 사원 8~12명, 부서 3개, 급여 일부 NULL).
3. 브라우저 안의 SQL 엔진(sql.js)에 테이블을 만들고 쿼리를 실행해 **정답을 계산**한다.
4. 오답 보기는 "흔한 실수"를 반영한 쿼리를 실제로 실행해 만든다 (예: NULL을 셌을 때의 건수, INNER JOIN으로 착각했을 때의 건수). 그래서 오답도 그럴듯하다.
5. 풀이 기록에는 템플릿 ID와 **시드**를 저장한다. 오답노트에서 다시 열면 똑같은 데이터의 문제가 재현된다.

화면에는 시험과 같은 Oracle 문법을 보여 주고, 실행은 SQLite 문법으로 한다. 둘의 차이는 `docs/04` §6의 변환 규칙으로 관리하며, 결과가 달라질 수 있는 문법(ROWNUM, 빈 문자열과 NULL, 정수 나눗셈 등)은 템플릿에서 의도적으로 다룬다.

## 5. 기술 스택과 선택 이유

| 영역 | 선택 | 이유 |
|---|---|---|
| 빌드 | Vite | 설정이 단순하고 빠름 |
| UI | React + TypeScript | 화면 상태(타이머, 선택한 답, 진행 상황)가 많아 컴포넌트 구조가 유리. 타입으로 문제 JSON 오류를 미리 잡음 |
| 라우팅 | react-router (HashRouter) | GitHub Pages는 서버 라우팅이 없어 `#/exam` 형태가 안전 |
| 스타일 | CSS Modules + CSS 변수 | 퍼블리싱 경험을 그대로 활용, 다크모드 토큰 관리 |
| 로컬 DB | IndexedDB + Dexie | 기기 안 영구 저장, 대용량, 쿼리 가능 |
| SQL 엔진 | sql.js (SQLite WASM) | 브라우저 안에서 진짜 SQL 실행 → 정답 자동 계산 |
| 테스트 | Vitest | Vite와 같은 설정, 채점·템플릿 로직 검증 |
| 배포 | GitHub Pages + PWA | 무료, 모바일 홈 화면 설치·오프라인 |

## 6. 데이터 모델

### 6.1 고정 문제 (`Question`)
세부 스키마는 `docs/04_문제출제기준.md` §5. 핵심 필드만:

| 필드 | 설명 |
|---|---|
| `id` | 고유 ID (예: `S2-JOIN-0007`) |
| `subject` | 1 또는 2 |
| `chapter` / `topic` | 단원 코드 / 세부 주제 |
| `type` | 문제 유형 (concept, sql_result, sql_error, sql_equivalent, modeling, scenario) |
| `difficulty` | 1~3 |
| `stem` | 문제 본문 (Markdown) |
| `tables` / `sql` | (선택) 예시 테이블, SQL |
| `choices` / `answer` | 보기 4개 / 정답 번호(1~4) |
| `explanation` | 해설 (Markdown) |
| `source` | `claude` / `user` |

### 6.2 템플릿 (`QuestionTemplate`)
코드로 작성하는 문제 생성기. `id`, `subject`, `chapter`, `topic`, `difficulty`, `generate(seed) → GeneratedQuestion`.

### 6.3 IndexedDB 테이블

| 테이블 | 주요 필드 | 용도 |
|---|---|---|
| `attempts` | id, questionRef(문제 ID 또는 템플릿 ID+시드), sessionId, mode, chosen, correct, elapsedSec, at | 한 문제를 푼 기록 1건 |
| `sessions` | id, mode(practice/exam/review), startedAt, finishedAt, questionRefs[], score, subjectScores, passed | 연습·모의고사 1회 |
| `notes` | questionRef, bookmarked, memo, mastered, updatedAt | 오답노트 상태·메모 |
| `userQuestions` | Question과 동일 (+createdAt, updatedAt) | 직접 추가한 문제 |
| `meta` | key, value | 설정, 시험 예정일, 스키마 버전 |

오답노트 목록은 별도로 저장하지 않고 `attempts`에서 "최근 시도가 오답인 문제"로 계산한다 (`notes.mastered=true`면 제외).

## 7. 화면 구성

| 화면 | 경로 | 주요 기능 |
|---|---|---|
| 홈(대시보드) | `#/` | 시험 D-day, 전체·과목별 정답률, 취약 단원 Top 3, 이어 풀기 |
| 단원별 연습 | `#/practice` | 필터(과목/단원/유형/난이도/안 푼 문제만) → 문제 풀이 → 즉시 해설 |
| 모의고사 | `#/exam` | 시작 안내 → 50문항(문항 이동 패널, 표시하기) → 90분 타이머 → 제출 |
| 결과 | `#/result/:sessionId` | 총점, 과목별 점수, 과락 여부, 문항별 정오, 해설 보기 |
| 오답노트 | `#/wrong` | 오답 목록(단원별 그룹), 다시 풀기, 메모, 북마크, 복습 모드 |
| 문제 관리 | `#/bank` | 전체 문제 검색·필터, 직접 추가/수정, JSON 가져오기/내보내기 |
| 설정 | `#/settings` | 시험일, 테마, 백업/복원, 데이터 초기화 |

모바일 기준: 하단 탭바(홈/연습/모의고사/오답/더보기), 보기 버튼은 손가락으로 누르기 쉬운 크기(최소 44px), SQL·테이블은 가로 스크롤 박스 안에 표시.

\* "세션"은 Claude Code를 켜고 한 번 집중해서 진행하는 단위. Phase 8은 사용량이 가장 많이 드는 구간이므로 단원별로 나눠서 진행한다.

**MVP(최소 실사용 버전)** = Phase 0~5 + Phase 8 일부(단원당 10문제) + Phase 9. 여기까지 오면 폰에서 공부를 시작할 수 있다.

## 9. 위험 요소와 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| Oracle과 SQLite 문법·결과 차이 | 템플릿 문제 정답 오류 | §6 변환 규칙, 템플릿마다 "Oracle 결과와 동일함"을 보장하는 테스트, 차이가 나는 문법은 고정 문제로 |
| AI가 만든 문제의 오류 | 잘못된 개념 학습 | SQL 문제는 sql.js로 실행 검증, 문제 화면에 "오류 신고" 버튼 → 오답 의심 목록으로 관리 |
| 기기별 기록 분리 | PC·폰 기록 불일치 | JSON 백업/복원 → Phase 10 동기화 |
| 브라우저 데이터 삭제 | 기록 유실 | 설정에 "마지막 백업 N일 전" 표시, 7일 넘으면 홈에 백업 권장 배너 |
| 출제 기준 변경 | 모의고사 비율 불일치 | `examRules.ts` 한 곳에서 관리 |
| Claude Code 사용량 | 콘텐츠 생성이 길어짐 | Phase 8을 단원 단위로 쪼개 여러 날에 걸쳐 진행 |

## 10. 저작권 원칙

- Claude가 만드는 문제는 자체 창작으로 한정한다.
- 사용자가 본인 교재를 보며 개인 학습용으로 직접 입력하는 문제는 `source: "user"`로 구분해 저장하며, 공개 배포(공개 저장소 커밋, 공유)는 하지 않는다. **GitHub 저장소를 public으로 만들 경우 `userQuestions` 내보내기 파일은 커밋하지 않는다.**
